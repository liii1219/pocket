# Pocket

DECO2850 原型。现在有多少时间 → 一节现成的课 → 摄像头检查动作。

## 跑起来

```bash
cd ~/Documents/deco2850/pocket
npm install       # 第一次才需要
npm run dev
```

打开 `http://localhost:5173`。

**手机上跑**（展台演示用）：`npm run dev` 会打印一个 `Network:` 地址，手机连同一个 WiFi 打开它。
⚠️ 摄像头需要 `localhost` 或 HTTPS，手机走局域网 IP 时浏览器会拒绝摄像头。
展台演示建议直接用笔记本，或者用 `npx vite --host --https`（自签证书，需在手机上信任一次）。

## 三个屏

1. **Time** — 只问一句"你现在有多少时间"，5 或 10 分钟
2. **Session** — 按时间 / 地点 / 酸痛部位 / 精力，当场编一节课，每个动作附一句为什么
3. **Coach** — 一次一个动作，摄像头数次数并给一条提示

从打开到第一个动作，**两下**。

## 为什么没有日历

第一版是"导入 `.ics` → 算出今天的空档 → 选一段"。做完发现方向错了。

采访里用户要的是**随时能开始**，而"先去导出一个日历文件再导进来"本身就是一次准备工作，
正好撞上第 4 条需求（不用做任何准备）。网页读不到系统日历，所以在网页上"用日历"必然
意味着"先导入"，这条路走不通。

日历相关的 439 行（`gaps.ts` / `ics.ts` 和它们的测试）已经删除，不留死代码。

## 设计上刻意不做的事

| 不做 | 为什么 |
|---|---|
| 连续打卡 streak | 受访者说漏一天整个计划就废了 |
| 体重 / BMI / 卡路里 | 伦理承诺，也和"看不懂指标"的发现冲突 |
| 数据面板 | 两位受访者明确拒绝可穿戴设备，理由是"又一层要解读的东西" |
| 让用户先配置时间表 | 卡点在"开始"那一刻，配置是把负担加在最脆弱的地方 |
| 导入日历 | 同上。导入文件本身就是准备工作 |
| 可浏览的动作库 | "只有 10 分钟的话，我不想花 5 分钟挑" |

## 隐私

MediaPipe 的 wasm 和模型都在 `public/` 下本地加载，**断网也能跑**。
摄像头画面只进 `<video>` 和内存，一帧都不上传、不落盘。

## 摄像头能判断什么

| 能判 | 靠什么 |
|---|---|
| 次数 | 主关节角的下潜-回位状态机,带迟滞阈值,临界抖动不会重复计数 |
| 蹲得够不够深 | 记录一次动作里的**最小膝角**,低于 110° 才算到位 |
| 是不是做太快(甩) | 单次耗时,快于 1.2 秒提示放慢 |
| 髋铰链还是屈膝 | 躯干倾角 vs 髋角,躯干还立着就提示"把髋推后" |
| 肩活动度够不够 | 一次里的最大抬起角 |

提示规则:**一次只说一条**(安全 > 幅度 > 节奏),而且**只在一次动作做完的那一刻说**,过程中不打断。
纠正过一次之后如果做对了,给一次确认就停,不反复夸。

## 已知限制（报告里要写）

- **2D 关键点看不见腰椎。** `checkHinge` 判的是躯干整体角度,不是"腰有没有塌"。真正的塌腰判定需要深度相机或腰部惯性传感器。代码注释里写明了。
- 膝盖内扣判不了,需要正面视角 + 深度信息。
- 侧面或斜 45° 拍最准;正对镜头时膝角会被压扁。
- 手机用局域网 IP 访问时摄像头会被浏览器拦（非安全上下文）。
